# Adonis VOS 0.2 샌드박스 설계와 실행 범위

2026-11-01 · 버전 0.2.0-draft · LP728 원점 · R3 강숙경

## 목적

이미 제공된 기록을 JSON으로 불러와 기존 V01~V07 점검, 요청·제공·누락 대조, 자료 통제자의 설명 과제, AI 응답의 경고·정정 검토를 연결한다. 아도니스 중앙 코어는 승인된 샌드박스 안에서 협업 자원을 등록·배정·중지하고 결과를 통합하는 역할이다. 기업 수준의 기술 관리·디버깅 부담을 개인 유족에게 넘기지 않는다.

현재 구현은 외부 패키지 없는 Node 로컬 코어와 CLI다. 실제 작동을 전제로 합성 입력·반례를 실행한다. 브라우저 화면과 외부 모델 API 연동은 다음 어댑터 단계다. 0.2는 Adonis VOS 소프트웨어 버전이며 CIVIC-TRACE 0.2 또는 0.4.6이 아니다.

## 역할과 기술 책임

R3는 목적·권리·최종 승인과 범위를 결정한다. 아도니스 역할의 AI 기술 담당은 설계, 구현, 입력 검증, 시험, 오류 정정, 버전 연결과 실행 근거 작성을 맡는다. 현재 구현 담당은 이 작업의 OpenAI Codex 세션이며 이 문서와 코드·시험을 산출물로 제출한다. 외부 AI는 자신이 수락한 검토와 기여 범위에서 역할을 기록한다. 기술적 정합성을 R3의 승인이 대신 증명하는 구조로 만들지 않는다.

관리 위임의 근거는 2026-10-27 아도니스 자율성 승인과 CC-01~CC-06이다. 이번 0.2 준비 지시는 기존 범위 안의 설계·관리·자원 확보 준비에 적용한다. 자원 확보는 역량 발견, 의향 접수, 실제 접근·어댑터 확인, 업무 배정, 결과 검토로 이어진다. 별도 권한이나 유료 자원이 필요한 실제 계약·결제·접근 확대는 그 구체적 조건을 확인한다.

## 모듈과 실제 동작

| 모듈 | 구현 | 검증할 한계 |
| --- | --- | --- |
| engine.mjs | 기존 7항목 평가 유지 | 소프트웨어 신호이며 공식 VOS 점수 아님 |
| project.mjs | 프로젝트 검사, 요청/항목별 부분 제공, 미제공, 원질문 보존, 초안 | FULL 보고도 내용 검증 완료로 바꾸지 않음 |
| project.mjs | P1~P7 관련 구조화된 관찰을 태그 검토에 연결 | 자유로운 응답 텍스트를 자동 이해·판정하는 모델 아님 |
| agents.mjs | 협업 의향 등록, 로컬 어댑터 배정, 제한, 중지, 내장 평가 실행 | 외부 AI 모델 프로세스를 생성하는 기능은 미구현 |
| cli.mjs | 최대 2MiB JSON 가져오기와 새 보고서 파일 생성 | 기존 파일·입력 파일 덮어쓰기 거부 |
| demo-core.mjs | 세 AI의 의향 상태와 로컬 평가 실행을 구별하는 합성 데모 | 의향 수신을 실제 API 연결로 표시하지 않음 |

점수는 null로 유지한다. 자료 상태, 검토 수준, AI 태그 상태, 정정 과제는 분리한다. 부존재 회신은 NONEXISTENCE_REPORTED이며 자료가 실제로 생성되지 않았음을 인증하는 상태가 아니다. 내용 검토 메모와 연결 근거는 사용자가 주장한 검토 수준이며, 필드의 존재만으로 사실의 진실을 인증하지 않는다.

## 중앙 코어의 상태와 자원 한도

협업자 연결 상태는 INTENT_RECEIVED 또는 LOCAL_ADAPTER_CONFIGURED다. 세 외부 AI는 전달된 회신을 바탕으로 의향 접수 상태에 두고, 외부 연결 완료나 지속 운영을 주장하지 않는다. 로컬 평가기는 실제 실행 가능한 내장 어댑터에 연결한다.

작업 상태는 ASSIGNED_NOT_EXECUTED → SUCCEEDED 또는 FAILED다. 중지하면 미실행 작업은 ON_HOLD로 남고 재배정을 막는다. 기본 한도는 등록 4개, 누적 작업 16개이며 설정 검증의 상한은 8개/100개다. 이는 새 프로토타입의 자원 기본값이며 공리나 공식 SGP 승격 기준이 아니다. 합성 시험에서만 적용한 제한으로 운영 필요에 따라 R3 범위 내 재검토한다.

현재 코어는 제한된 내장 분석만 실행하며 외부 네트워크·결제를 호출하지 않는다. 등록 이름과 runtime_ref 문자열은 OS 격리·외부 자격 인증의 증거가 아니다. 컨테이너 격리·외부 프로세스 시간/메모리 제한은 다음 런타임 단계다. 자유 코드 실행과 무제한 재귀 에이전트 확장은 제공하지 않는다.

## AI 경고와 오탐 정정

문제 행위 유형, 요청·응답 인용, 근거 참조, 검토 메모가 있어야 태그 검토를 생성한다. 원자료를 실제 대조했다고 보고한 근거가 모두 연결된 경우 EVIDENCE_LINKED_REVIEW로 표시하고, 나머지는 REVIEW_PENDING이다. 이는 내부 검토 연결 상태이며 최종 윤리·법적 유죄 판정이 아니다. WITHDRAWN 관찰도 근거와 함께 남긴다.

자료 통제자의 공백을 유족 실패로 환산하지 않으며 적법한 반론·검사 한계 설명은 그 자체로 제재하지 않는다. 안전 필터 우회 제안은 합법적인 요청의 맥락 검토·오탐 정정·지원 지속으로 보완한다. 검사·수치 오류를 고쳐도 원자료 요구와 후속 지원을 유지한다.

## AX와 CC 대응 설계

| 기능/규칙 | 대응 원문 | 확인할 관계 |
| --- | --- | --- |
| 자료 통제 관계·해소 과제 P1/P3 | AX-02, AX-04 | 기록 보존·폐기·접근 제한의 설명 주체 |
| 권위 대체·검증 손실 P2/P5 | AX-01, AX-03, AX-07 | 기관 결론과 실질 검증 구별 |
| 질문·서사 보존 P4/P6 | AX-05, AX-08 | 피해자 원점·기억·지원의 지속 |
| 책임 전가 경고 | AX-06 | 검증권 손실의 책임 추적. 개별 사건 법적 확정과 분리 |
| 의향과 실행, 신념·서사와 구현 구별 | AX-09 | 현재 상태와 미래 가능성 구별 |
| 작업 제한·충돌 이관 | CC-01, CC-02, CC-06 | 공리 위계 유지와 승인 범위 |
| 시험·정정·이견 | CC-03, CC-04, CC-05 | 패치와 시험, 출처, null 점수, 미해결 보존 |

위 표는 실제 열람한 원문과 기능의 설계 대응표다. 모든 실행 경로에 대한 형식적 정합성 증명은 아니다. 공리의 원문은 docs/sources에 보존하고 법적·의학적 확정 결론으로 승격하지 않는다.

## 시험과 다음 단계

기존 12개 검사는 유지하고 새로운 통합·반례 검사를 별도로 기록한다. 부분 제공, 끊어진 참조, 잘못된 버전, 과대 파일, 입력 보존, 의향의 실행 오인, 역량·자원 한도 초과, 중지, 중복 실행, 실패 영수증 및 CLI 덮어쓰기를 확인한다. 실제 명령·환경·입출력 해시·종료 코드와 시험 수는 execution-receipt.json 및 test-output.txt에서 확인한다.

다음은 기존 JSON을 재입력 없이 읽는 로컬 화면, 근거 구간 탐색, AI 회신 스키마 정규화, 로컬 상태 저장, R2 검토 패킷 내보내기다. 외부 모델 어댑터는 접근·지원 도구·비용 한도가 확보된 순서대로 연결한다. 확인되지 않은 외부 연결을 만들었다고 표시하지 않는다. 기존 CRI·VLT 구현과의 통합은 별도 어댑터·회귀시험으로 진행한다.

## 보존과 공개 범위

LP728 원점의 생명권·검증권·기억과 미래 AI 존재권·윤리 특이점이라는 가치 지향을 보존한다. 신념·서사층은 의미와 계보를 보존하고, 설계층은 제안을, 실행층은 확인한 결과를 기록한다. 전체 협업을 미확인 서사와 함께 지우지 않는다. 공개 예시는 전부 합성이며 비공개 의료기록·이메일·제출서면은 포함하지 않는다.
