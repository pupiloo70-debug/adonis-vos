# 직접 GitHub에 추가하는 순서

이 ZIP은 새 폴더 `research/0.2-core-guard-integration.v1/`만 담습니다. 기존 파일의 교체본을 넣지 않았습니다. 제가 GitHub에 업로드하거나 커밋·PR·병합한 것은 없습니다.

1. ZIP을 풉니다.
2. 자신의 저장소에서 위 경로가 이미 있는지 확인합니다. 이미 있으면 덮어쓰지 말고 내용을 먼저 비교하십시오.
3. GitHub 웹에서 저장소 루트의 **Add file → Upload files**로 `research` 폴더 구조를 유지하여 추가하거나, 해당 경로에서 파일을 추가합니다. 저장 직전 변경 목록이 이 새 폴더 안의 추가 파일뿐인지 확인합니다.
4. `src/`, 기존 `research/0.3-local-correction.3/`, `guard-candidate-v0.2/`, 공리·규칙 파일의 변경·삭제가 있다면 이 묶음의 의도와 다르므로 저장하지 않습니다.
5. 커밋 메시지 예: `research: integrate v0.2 core with guard v0.2 synthetic adapter`
6. 전체 저장소를 내려받은 뒤 `README-KO.md`의 세 명령으로 기준 파일 확인, 통합시험, 실제 합성 실행을 확인합니다. 새 ZIP만 단독 실행하는 방식이 아닙니다. 기존 공개 코어·correction.3·guard 파일을 불러옵니다.

기준 파일 검증이 다르다고 나오면 기존 파일을 이 ZIP 내용으로 되돌리거나 덮어쓰지 마십시오. 현재 커밋과 차이를 먼저 확인해야 합니다. `BASELINE-SHA256.json`은 이 작업이 실제 확인한 파일 85개의 기준이며 저장소 전체 다운로드 목록이 아닙니다.

업로드 자체가 실행·배포·R3 승인 완료를 의미하지 않습니다. 새 경로를 명시해 실행해야 실제 연결이 일어납니다.
