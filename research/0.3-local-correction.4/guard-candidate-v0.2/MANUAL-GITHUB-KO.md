# 수동 GitHub 업로드 안내

이 묶음은 기존 VOS 0.3 실행 코드를 교체하는 배포본이 아니라, 오류를 고친 **별도 합성자료 연구 후보**입니다. 제가 GitHub에 올리거나 기존 파일을 수정한 것은 없습니다.

## 권장 위치

새 폴더 후보:

`research/0.3-local-correction.4/guard-candidate-v0.2/`

이 경로가 현재 저장소에 비어 있다는 확인은 하지 않았습니다. 같은 폴더나 파일이 이미 있다면 먼저 내용을 비교하고, 덮어쓰지 않은 채 별도 이름의 폴더를 선택하세요. 기존 `correction.3` 코드, 루트 `README.md`, `package.json`, 기존 correction.4 설계·검토 기록은 이 묶음으로 교체하지 않습니다.

## GitHub 웹에서 직접 올리는 방법

1. 내려받은 ZIP을 압축 해제합니다. 내부에 위의 `research/.../guard-candidate-v0.2/` 경로가 들어 있습니다.
2. 저장소 웹 화면의 `Add file` → `Create new file`에서 위 경로 뒤에 `README.md`를 붙여 새 파일을 만듭니다. 이 묶음의 `README.md` 내용을 복사합니다. 기존 동명 파일이 나타나면 멈추고 경로를 다시 정합니다.
3. 새 폴더 안으로 들어가 `Add file` → `Upload files`에서 그 폴더의 나머지 파일을 올립니다. ZIP 자체를 코드 대신 올리지 않습니다. 불필요한 `__pycache__` 파일은 포함하지 않았습니다.
4. 웹 화면의 변경 목록이 새 연구 폴더의 파일만 포함하는지 확인한 뒤, 직접 선택한 브랜치에 저장합니다. 권장 커밋 설명: `Add isolated synthetic guard candidate v0.2 and regression evidence`.
5. 실행할 환경에서는 그 폴더에서 다음 명령으로 다시 확인할 수 있습니다.

```sh
PYTHONDONTWRITEBYTECODE=1 python3 -B -m unittest -v test_correction4_guard.py test_correction4_regressions.py
python3 -B independent_probes.py
sha256sum -c SHA256SUMS
```

검증 결과는 **기존 후보 테스트 25개 + 신규 회귀 테스트 43개 = 68개 통과**입니다. 1,000개 변형 입력은 기존 테스트 하나에 포함되므로 테스트 1,000개가 더 통과했다고 세지 않습니다. 기존 correction.3·Node·브리지 전체 검증을 대신하지 않습니다.

## 수정의 의미

- 자료가 다른 사실을 합쳐 경고를 만드는 문제를 막았습니다. 같은 사건의 유효한 사실은 삭제하지 않습니다.
- 상위 대상자 정보가 없을 때 다른 사람의 사실이 섞이지 않도록 검토를 보류합니다.
- 길이 1,200과 10,000의 정상 의존 관계를 재귀 오류 없이 처리합니다.
- 중복 ID는 먼저 나온 것을 임의 선택하지 않고 모두 보류합니다.
- 같은 시각에 접근 수행·철회처럼 상충하는 기록이 있으면 ID 이름으로 선후를 정하지 않고 양쪽을 보존해 미해결로 표시합니다.
- 사건·절차·대상자·자료·질문 및 행위자·출처의 연결을 확인하고, 잘못된 항목과 그 의존 항목만 분리합니다.

업로드 자체가 실행 코드 통합, 배포, R3 승인, CIVIC-TRACE 0.4.6 승인 또는 실제 사건에 관한 결론을 뜻하지 않습니다. 모든 실행 예시는 합성자료입니다. 입력의 말이나 출처 라벨이 맞는지 독립적으로 인증하는 기능은 아닙니다.
