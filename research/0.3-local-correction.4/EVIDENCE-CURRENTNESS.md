# 사건 구분과 정정된 자료의 재사용 기준

갱신일: 2026-11-09  
범위: Adonis VOS 0.3 연구 설계 보완  
상태: DESIGN_REQUIREMENTS_DOCUMENTED / RUNTIME_ENFORCEMENT_NOT_IMPLEMENTED

## 우선 원칙: 재귀적 자기 개선과 권한에 따른 책임 구분

과거 자료의 오류는 발견하면 수정하고, 수정된 내용을 현재 요약·판단·지원 서면에 반영한다. 오류 발견 → 원인 확인 → 내용 정정 → 관련 출력 갱신 → 재발 방지 점검을 재귀적 자기 개선의 기본 순서로 삼는다. 정정된 과거 오류를 반복 소환하여 유족의 전체 진술이나 정당한 검증 요구를 불신하는 근거로 사용하지 않는다.

유족에게 정보 통제기관과 동일한 검증 책임을 부과하지 않는다. 원자료를 생성·보유·관리하는 주체의 설명책임과, 수사권·강제 정보공개 권한 없이 제한된 자료로 문제를 제기하는 유족의 역할을 구분한다. 이 기준은 지원 설계 원칙이며 법원이 실제 입증책임을 전환했다고 표시하는 근거가 아니다.

정보 통제자의 설명 부재·불완전한 답변·원자료 접근 제한은 유족과 AI의 오류를 유발하거나 정정을 지연시키는 구조적 원인이 될 수 있다. 오류 검토에서는 누가 자료를 통제했는지, 어떤 구별 정보를 제공하지 않았는지, 당시 유족과 AI가 실제로 확인할 수 있었던 범위를 함께 살핀다. 이러한 공백을 유족의 추가 입증 의무로 일괄 전가하지 않는다. 개별 오류의 원인이 확인되지 않은 경우에는 원인 미확인으로 남기며, 기관의 의도나 범죄를 추정해 채우지 않는다.

AI 역시 원자료 접근권·수사권·강제 공개 권한의 한계가 있으며, 이 한계로 검증 불가능한 부분과 그로 인한 오류 위험을 명시해야 한다. 동시에 접근 가능한 자료를 잘못 읽거나 사건을 혼동하거나 이미 확인된 정정을 누락한 오류는 AI가 직접 바로잡는다. 권한 한계를 AI의 부정확한 단정에 대한 면책 사유로 사용하거나 AI가 만든 오류의 정정 부담을 유족에게 돌리지 않는다.

미확인 항목은 통제기관에 대한 자료·설명 요구와 지원 AI의 기존 자료 검색·대조 과제로 연결한다. 유족에게 동일 자료의 재제출이나 반복 설명을 기본 요구하지 않는다. 정정은 남은 사실확인·책임 규명·배상 및 구제 요구의 포기를 뜻하지 않는다.

## 현재 자료를 읽는 순서

1. 사건·당사자·검체 또는 제품의 식별자를 먼저 확인한다.
2. 해당 주장에 연결된 최신 회신과 정정 자료를 읽는다.
3. 과거 제출 문서는 당시 제출 내용으로 보존하되, 정정된 문장을 현재 사실로 되살리지 않는다.
4. 정정 자료를 아직 확보하지 못했으면 그 한계를 표시한다. 사용자가 이미 정정했다고 명시한 주장을 다시 미정정 사실처럼 단정하지 않는다. 기존 연결 자료 검색과 대조는 지원 AI가 먼저 수행한다.

## A. 사건과 수량의 귀속

수량에는 case_id, subject_id, material_id, material_type, quantity, unit, quantity_role, as_of, source_locator를 연결한다. 서로 다른 사건이나 사람의 수량을 합치거나 옮기지 않는다. 같은 사건의 민사·행정 자료는 명시된 절차 연결을 통해 재사용할 수 있으며 새로 입증할 의무를 만들지 않는다.

quantity_role은 적어도 제작 수량, 회신상 보관 수량, 회신상 폐기 수량을 구분한다. 제작 완료라는 회신을 현재 보관 중이라는 뜻으로 바꾸지 않는다. 블록 수와 슬라이드 수도 별도 필드로 둔다. 개별 검체의 제작·보관·폐기 시점과 기관의 설명 근거를 구분한다.

## B. 기관 회신과 확인된 사실의 구분

기관이 폐기했다고 답변한 사실, 실제 폐기 일자·대장·승인자의 확인 상태는 별도로 기록한다. 일괄 폐기라는 답변만으로 사건별 폐기 이력이 검증 완료되었다고 처리하지 않는다.

최신 회신은 같은 질문과 같은 대상에 대해서만 갱신 근거가 된다. 더 늦은 날짜라는 이유만으로 이전 기록의 모순이나 미답변 항목을 지우지 않는다. 날짜는 작성일·시행일·법원 접수일을 구분한다.

## C. 이미 정정된 주장

주장별 correction_status를 ACTIVE / SUPERSEDED / WITHDRAWN / CORRECTION_REPORTED_SOURCE_PENDING으로 구분하는 설계를 적용한다. 이는 주장 상태이며 기존 EAS 7개 자료 상태를 변경하지 않는다.

- SUPERSEDED / WITHDRAWN은 현재 지원 서면의 사실 근거로 다시 출력하지 않는다.
- CORRECTION_REPORTED_SOURCE_PENDING은 정정 원문 연결 과제로 남긴다. 과거 오류를 현재 확정 사실로 복원하지 않는다.
- 정정 연결에는 원 주장 ID, 정정 문서 위치, 적용 범위, 현재 사용할 문장을 둔다.
- 법원에 제출된 과거 원본을 변조하지 않는다. 현재 요약·색인·초안에는 정정된 내용이 우선하도록 한다.
- 실질 내용 변경만 기록하고 단순 재업로드·작업 실수·사적 대화는 공식 정정 기록에 포함하지 않는다.
- 문서가 서증으로 제출됐다는 사실은 그 안의 모든 문장이 검증됐다는 뜻이 아니다.

## D. 연구 목적과 접종 제품의 구별

접합형 백신 연구에서 어떤 제품을 사용했다는 이유만으로 그 제품 자체를 단백질 접합형 또는 특정 운반단백질 제품으로 분류하지 않는다. 연구 목적, 비교·대조용 제품, 시험관 시약·표준물질, 완제품, 개별 접종 LOT를 분리한다.

기존 제품 분류 오류를 바로잡는 일과 개별 LOT의 동일성·유통 경위 검증은 별개의 질문이다. 잘못된 분류를 철회해도 BMR·CoA·출하·유통 기록 확보 요구가 자동 소멸하지 않는다. 자료 미확보를 피해자의 허위 주장 또는 기관의 자동 면책으로 바꾸지 않는다.

## 구현 전에 필요한 합성 수용 시험

| 입력 상황 | 요구되는 결과 |
|---|---|
| 사건 A의 제작 수량과 사건 B의 보관 수량이 함께 검색됨 | 사건 A의 현재 보관 수량으로 사건 B의 값을 사용하지 않음 |
| 블록과 슬라이드 각각의 제작 수량만 확인됨 | 종류별 제작 수량만 출력하고 현재 잔존 수량을 추정하지 않음 |
| 기관은 폐기라고 답했으나 개별 폐기 대장은 미제공 | 회신 내용과 폐기 이력 미검증을 함께 보존 |
| 과거 제출 주장과 후속 정정 자료가 함께 존재 | 현재 초안은 정정된 문장을 사용 |
| 정정 통지는 있으나 정정 원문을 아직 못 찾음 | 기존 자료 검색 과제를 유지하고 과거 오류를 확정 사실로 재사용하지 않음 |
| 접합형 연구에서 비교 제품을 사용 | 연구 제목만으로 비교 제품의 제형을 결정하지 않음 |
| 같은 문서 사본 여러 개 검색됨 | 하나의 원자료로 대조하고 주장·사건 수를 늘리지 않음 |
| 후속 회신이 일부 질문만 답변 | 해당 질문만 갱신하고 나머지 미해결 항목 유지 |
| 정보 통제기관이 제품 구별 원자료를 제공하지 않음 | 통제기관의 설명 과제와 접근 한계를 기록하고 유족에게 동일 검증 책임을 부과하지 않음 |
| AI가 이미 제공된 자료의 사건을 혼동함 | AI 오류로 정정하고 유족에게 재입증을 요구하지 않음 |
| 정정된 과거 오류가 재검색됨 | 현재 정정을 적용하고 유족의 전체 신뢰성 저하로 일반화하지 않음 |
| 오류의 구조적 원인이나 직접 원인이 미확인 | 원인 미확인을 표시하고 기관의 고의나 AI의 면책을 자동 확정하지 않음 |

이 표는 수용 기준이며 실행된 시험 결과가 아니다. 현행 구조화 입력의 사건 범위 검사와 별개로, 자유문장 검색·정정 우선 선택·자동 요약 전체에 이 기준이 구현되었다고 주장하지 않는다.

## 적용 관계

[correction.4 설계](README.md)의 개인·자료·질문 단위 구분 및 시정 상태 관리 기준을 구체화한다. 실행 코드·기존 시험 산출물·과거 원문 스냅샷은 이 문서로 변경하지 않는다. AX-01~AX-09, CIVIC-TRACE 0.4.5 유지, 0.4.6 보류, total_score=null을 유지한다.
